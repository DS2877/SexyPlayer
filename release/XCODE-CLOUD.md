# Xcode Cloud — why Build 7 failed and the fix

## The error

```
xcodebuild: error: '/Volumes/workspace/repository/Aeria.xcodeproj' does not exist.
Project Aeria.xcodeproj does not exist at the root of the repository
```

## Why

`Aeria.xcodeproj` is **generated by XcodeGen from `project.yml`** and is
deliberately not committed (`.gitignore`: *"The .xcodeproj is generated by
XcodeGen from project.yml — never commit it."*). On your Mac it exists because
you run `xcodegen generate` before opening it. Xcode Cloud clones the repo and
runs `xcodebuild` straight away — there's no project for it to build.

Same reason these are also generated (and gitignored), and Xcode Cloud needs
them too:

- `Sources/App/Info.plist`, `Sources/App/Aeria.entitlements`
- `Sources/TopShelf/Info.plist`, `Sources/TopShelf/AeriaTopShelf.entitlements`

## The fix (committed)

`ci_scripts/ci_post_clone.sh` — Xcode Cloud runs any script at that exact path
right after cloning, before it resolves packages or builds. The script:

1. Makes sure Homebrew is on `PATH` (it's preinstalled on Xcode Cloud images).
2. `brew install xcodegen` (skipped if a previous build cached it).
3. `xcodegen generate` at the repo root → produces `Aeria.xcodeproj` **and**
   the four plist/entitlement files.

`.gitattributes` now also pins `*.sh` to LF endings, so the script's `#!/bin/sh`
line survives being committed from a Windows machine (CRLF would break it on
macOS).

## If it still fails after that

- **"No profiles for 'com.aeriaplus.appletv' were found"** → in App Store
  Connect, the Xcode Cloud workflow's *Archive* action needs the bundle IDs
  (`com.aeriaplus.appletv`, `.topshelf`) and the App Group
  (`group.com.aeriaplus.appletv`) registered, and automatic signing enabled for
  the workflow. Builds 1–6 uploaded fine, so this is probably already set — but
  Xcode Cloud manages its own signing assets separately from local Xcode.
- **XcodeGen rejects `type: com.apple.product-type.tv-app-extension`** →
  `project.yml` line 87, change to `type: app-extension`. (Latest XcodeGen
  accepts the raw type; your local build already proves it works.)
- **A Swift compile error the local build didn't catch** → Xcode Cloud uses
  Xcode 26.6; if your local Xcode is older, paste the error.
